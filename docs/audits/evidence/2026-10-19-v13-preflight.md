This supersedes the earlier assumption that only the previously qualified v14
pair would be tested. It does not turn prior v14 or isolated fixtures into v13
acceptance, and no v13 support change has yet been implemented.

accepted dropping Foundry13/native5.1.2 support and following upstream's

this release; v13 acceptance is not a closeout requirement. The findings below

## MB-V13-01 — world-rule declarations exclude native5.1.2

`info.json:worldSettings` declares both the setting and registered-default ranges
as `>=6.0.0 <=6.0.1` for `trackCarryingCapacity`, `trackAmmo`, `hitAutomation` and
`allowedScvmClasses`. Core's `ModuleWorldContextService.resolve` correctly reports
`unavailable / unsupported-version` outside that declaration, including when the
native world has an explicit value. This is not missing permission or a failed
native settings read.

The current compiled package was installed in a new isolated exact-Core archive,
using the actual production registry, world-context and caller request services.
Synthetic context was set to Foundry13.351/native5.1.2. The two cases below used
deterministic transport and did not connect that Core instance to Foundry:

| Input | Actual result |
| --- | --- |
| No explicit world setting records | All four settings unavailable/unsupported-version; Strength route503 `Carrying rules are unavailable`; classes route503 `Native setting allowedScvmClasses is unavailable (unsupported-version)` |
| All four valid explicit setting records present | Identical unavailable settings and route503 results |

Both cases preserve Actor source and produce zero dice, chat or document effects.
Prepared `derived.encumbered` is null. These are passing **refusal checks**, not
passing v13 gameplay. They demonstrate why the corrected native action paths
cannot all be accepted on the current artifact; they do not assert that every
inventory/read operation is blocked or that Core itself cannot serve v13.

Trace: `src/server/MorkBorgAdapter.ts:prepareActorData` →
`src/logic/worldRules.ts:ruleResult` → carrying availability in `getRollData`;
class catalog → `requireRule(..., 'allowedScvmClasses')`.

## Bounded compatibility investigation

Read-only source comparison of local tags5.1.2 and6.0.1, plus decoded **copies**
of all four pack databases, found:

- `module/settings.js`, `module/config.js`, `template.json`, Item preparation,
  ability tests, rests, powers and advancement sources inspected are unchanged.
- The attack change replaces `getProperty(ammo, 'system.quantity')` with
  `ammo.system.quantity`; it does not change the quantity rule.
- Item and table rows are identical after excluding `_stats` audit metadata:
  237 Item-pack rows and660 Table-pack rows, including their embedded records.
- Both Actor packs have42 rows. Their26 root Actors differ in `prototypeToken`
  representation; no other semantic field differs under that comparison. For
  example, the Owl has v13 `detectionModes: []` versus v14 `{}`, different texture
  fields and a new v14 `depth`. Preserve the selected source's token fields.
- The reviewed Create Decoctions macro has the same UUID and command SHA-256
  `a6d10961ae7aece8592a9ce30a94eace6e7a4a374d592b1826f4e776941abdd7`.
  Its sort order differs. Native6.0.1 adds four ability macros absent from5.1.2;
  they are not prerequisites for the module's own shared ability actions.
- Remaining upstream differences include native sheet/dialog/combat hooks and
  presentation. Those browser changes are not a reason to import native runtime
  or change SheetDelver's ownership boundaries.

This establishes a concrete starting point for a narrow module compatibility
change, not complete v13 parity. Live content may be customized and still needs
caller-visible validation and source preservation during acceptance.

## Historical correction proposal — not selected

The following proposal was prepared before the user declined v13 support. It is
retained for traceability only. It is not an implementation task or release gate;
reconsider it only if the user explicitly selects legacy native5.1.2 support.

### Proposed checkpoints

1. After scope approval, retain these failing-availability expectations as the
   before case, then declare proven5.1.2 setting/default provenance alongside the
   existing6.0.x profile. Do not change Core/SDK or module release versions.
2. Use only Core0.19.3's supported range syntax. Its compatibility resolver
   accepts conjunctive constraints, not `||`. If a coarse declaration spans
   unqualified versions, add a module-owned exact profile guard rather than
   silently claiming all intervening patches or requesting a speculative Core
   extension. Keep unknown/native-newer cases unavailable before effects.
3. Run source and installed-package checks with independently decoded5.1.2
   fixtures, including both setting-presence cases, all four abilities, class
   availability, exact ammo, passive/formula/reviewed macros and source retention.
   Adapt the unsupported-macro fixture to5.1.2's one-macro inventory; do not assume
   that a different native macro must exist there.
4. Then execute the [five correction paths](2026-10-19-correction-review.md#bounded-native-follow-up-and-closeout)
   on the current disposable v13 world. Because this is the first native v13
   qualification, also record a bounded compatibility smoke for settings refresh,
   Actor/Item source shapes, class generation and complete companion token data.
   Preserve broader unexecuted MB-A cases as qualified/pending rather than
   attributing the old v14 matrix to v13.
5. Verify fixture cleanup before requesting v14. Re-run the corrected paths on
   v14 and retain each pair's exact package/source identities. Closeout must state
   the actual native coverage and any outstanding scope decisions honestly.

The user chose the existing v14 support boundary. The approval question is resolved;
no declaration or application source was changed. Resume the five corrected-path
checks on Foundry14/native6.0.1, then reconcile G8/G9. The v13 world was only read
through public status/served-source endpoints, so it has no test fixtures to clean up.
